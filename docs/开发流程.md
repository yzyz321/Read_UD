# UdiskTools 项目开发流程

> 适用：本仓库全部开发活动。配合《软件规划书》的 Phase 1–3 计划执行。

## 1. 分支模型

| 分支 | 用途 | 保护 |
|---|---|---|
| `main` | 稳定发布分支，始终可构建可运行 | 只接受 PR，禁止直接 push |
| `dev` | 集成开发分支，功能合入的集散地 | PR 合入，CI 必须通过 |
| `feature/<主题>` | 单个功能开发 | 自由提交 |
| `fix/<问题>` | 缺陷修复 | 自由提交 |

示例：`feature/ini-parser`、`feature/device-polling`、`fix/dpi-resize`

## 2. 提交规范（Conventional Commits）

```
feat: ini 解析器支持注释保留写回
fix: WM_DPICHANGED 后字体未重建导致模糊
docs: 更新控件命名表
refactor: 提取 pattern.c 通配符匹配
chore: CI 增加 artifact 上传
```

一条提交只做一件事；提交信息说明"为什么"而不只是"改了什么"。

## 3. 日常迭代循环

```
1. git switch dev && git pull
2. git switch -c feature/<主题>      # 从 dev 拉出
3. 开发（小步提交，每步保证可编译）
4. 本地 make（或 cmake --build）自测
5. push 到远端 → CI 构建通过
6. 发 PR 到 dev → 代码自查 → 合并
7. 删除 feature 分支
```

## 4. 阶段发布

- 每个 Phase 结束打 tag：`v0.1.0`（M1 CLI 引擎）、`v0.2.0`（M2 GUI）、`v1.0.0`（M3 发布）
- tag 触发 CI 产出 exe artifact，作为阶段交付物
- 版本号与 `src/version.h`、ini 的 `VERSION` 键三处保持一致（发版前统一检查）

## 5. 质量门禁

- CI 必须绿（编译零 error；`-Wall -Wextra` 下不新增 warning）
- 影响控件布局的改动必须对照 `docs/mockup/index.html` 与 `ui/resource.h`
- 涉及 ini 格式的改动必须同步：规划书、`profiles/UdiskTools.ini`、解析代码三处一致
- 日志相关改动：确认"日志强制输出"红线未被破坏

- MinGW-w64 工具链：推荐 [w64devkit](https://github.com/skeeto/w64devkit) 或 MSYS2（`pacman -S mingw-w64-x86_64-gcc`）
- 本机当前状态：git ✅、make ✅、cmake ✖（可选，用 Makefile 即可）、gcc ✖（仅有 clang，需装 MinGW-w64 或配置 clang 的 mingw 目标）
