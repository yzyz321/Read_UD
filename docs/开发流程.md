# UdiskTools 开发流程

> 适用版本：软件 v1.2.0（2026-10-24；配置文件版本由 ini `[TOOLSINFO] VERSION` 决定，二者独立）　目标读者：研发、测试、CI 维护者
> 关联文档：[软件规划书](UdiskTools软件规划书.md)、[UI 功能状态说明](UI功能状态说明.md)、[变更记录](CHANGELOG.md)、[文档索引](README.md)

## 1. 环境与依赖

| 依赖 | 说明 |
|---|---|
| Windows 10/11 x64 | 运行与构建目标平台 |
| MinGW-w64（gcc 或 llvm-mingw） | `gcc`、`windres`（资源编译）、`mingw32-make`/`make`；CI 使用 MSYS2 MINGW64 |
| PowerShell 7（`pwsh`） | 生成/校验脚本、测试脚本、CI 步骤 |
| git | 版本管理；`core.autocrlf` 会使工作区文本为 CRLF（生成器已按内容归一化，见 §4） |
| CMake ≥3.15 | 备用构建（`CMakeLists.txt`），正式构建以 Makefile 为准 |
| dbghelp | 崩溃转储（Makefile/CMake 已链接） |

## 2. 构建

### 2.1 Make（主路径）

```powershell
cd udisktools
make                 # 产物 bin/udisktools_v<软件版本>.exe（含 windres 资源 + dbghelp 链接）
make run             # 构建并运行
mingw32-make check-default-ini   # 默认配置一致性校验（不构建）
make clean           # 清理 bin/ 与资源中间产物
```

构建命令（Makefile）：

```
gcc -std=c11 -Wall -Wextra -DUNICODE -D_UNICODE -D_WIN32_WINNT=0x0605 -Iui -Isrc ...
windres -I res -I src -o bin/udisktools_res.o res/udisktools.rc
链接加入 -municode -mwindows ... -ldbghelp
```

### 2.2 CMake（备用）

```powershell
cmake -B build -G "MinGW Makefiles"
cmake --build build
```

### 2.3 编译检查（不产物）

改动后可先用语法检查快速发现告警：

```powershell
gcc -std=c11 -Wall -Wextra -DUNICODE -D_UNICODE -D_WIN32_WINNT=0x0605 -Iui -Isrc -fsyntax-only src/*.c
```

质量要求：**零 error；`-Wall -Wextra` 下不新增 warning**。

## 3. 测试与本地校验

| 项 | 命令 | 说明 |
|---|---|---|
| 默认配置一致性 | `pwsh scripts/gen_default_ini.ps1 -Check` 或 `mingw32-make check-default-ini` | 生成结果与 `src/default_ini.h` 逐字节比较；失败会打印差异摘要（exit 1） |
| 单元/回归测试 | `pwsh tests/run_tests.ps1`（第 7 批 B 线入库；可用 `-CC gcc`/`-CC clang` 指定编译器） | 输出 PASS/FAIL 汇总；CI 以 `tests/run_tests.ps1 -CC gcc` 调用（见 `build.yml`） |
| CLI 冒烟 | `bin\udisktools_v1.2.0.exe --version`、`--check-ini --ini profiles\UdiskTools.ini`、`--check-ini --ini no_such.ini` | 期望退出码分别 0/0/1；`--version` 应含**软件版本 1.2.0** 与构建时间，`--check-ini` 应含**配置文件版本**；CI 用 `Start-Process` 重定向捕获 stdout |
| 测试目录 | `tests/unit`、`tests/integration`、`tests/fixtures` | 由 `tests/run_tests.ps1` 驱动；若脚本缺失说明当前工作树尚未合入测试批次，不要伪造通过 |

> 安全约定：**不要对真实 U 盘执行写入/格式化类测试**；需要磁盘的用例使用临时目录/`subst` 虚拟盘，并在用例结束后清理。`temp_run/`（工作区根目录、仓库外）是临时调试/测试运行目录，**不纳入构建/测试清理，禁止删除或改动**。

## 4. ini / 默认配置同步规则（CI 硬门禁）

1. `profiles/UdiskTools_default.ini`（内嵌默认配置的**生成源**）与 `src/default_ini.h` **必须在同一批提交**（`default_ini.h` 由 `scripts/gen_default_ini.ps1` 从 profiles 生成；ini 缺失启动与配置窗口[恢复默认设置]共用该内嵌常量）。
2. 改 ini 键/语义/默认值必须同步：`profiles/UdiskTools.ini`、`profiles/UdiskTools_default.ini`（若涉及默认值）、`src/default_ini.h`（重生成）、[使用手册](配置文件使用手册.md)、[规划书](UdiskTools软件规划书.md)（§4.4/§7.4）。
3. 生成脚本有两份等价实现：`scripts/gen_default_ini.ps1`（CI 与 Makefile 使用）和 `scripts/gen_default_ini.py`（历史实现，需保持同一输出）；生成器已容忍 LF/CRLF 工作区差异。
4. CI 在 Build 前执行 `./scripts/gen_default_ini.ps1 -Check`；不一致即失败。

## 5. CI 门禁（`.github/workflows/build.yml`）

触发：`push` / `pull_request` 到 `main` / `dev`。步骤：

| 顺序 | 步骤 | 作用 |
|---|---|---|
| 1 | Setup MinGW-w64（MSYS2 MINGW64） | 安装 gcc + make |
| 2 | **Check default ini template**（pwsh） | `scripts/gen_default_ini.ps1 -Check`，防默认配置漂移 |
| 3 | **Build (make)**（msys2 shell） | `make CC=gcc` 产出 `bin/udisktools_v<软件版本>.exe` |
| 4 | **Run tests**（pwsh） | `tests/run_tests.ps1 -CC gcc`，回归/单元测试门禁 |
| 5 | **Smoke test (CLI)**（pwsh） | `--version`（0，含**软件版本 1.2.0**/构建时间）、`--check-ini` 有效配置（0，含机型数与**配置文件版本**）、不存在 ini（1），不弹窗阻塞 |
| 6 | Upload artifact | 上传 `bin/udisktools_v*.exe` |

> 若本地能通过而 CI 失败，优先检查：默认配置是否同批提交、`pwsh` 脚本是否使用 Windows 路径、CLI 是否误弹窗（GUI 子系统需重定向捕获输出）。

## 6. 提交规则

- **提交信息**：Conventional Commits（`feat:` / `fix:` / `docs:` / `refactor:` / `chore:` / `test:`），说明"为什么"而不只是"改了什么"；一条提交只做一件事。
- **禁止提交**：`bin/`、`build/`、`obj/`、`*.o`、`*.exe`、`logs/`、`*.log`、崩溃转储 `*.dmp`、本地 scratch 目录（`.gitignore` 已覆盖大部分，提交前 `git status` 复核）。
- **文档同步**：代码/行为改动必须同步相关文档（对照 [文档索引](README.md) §3 维护规则）；用户交付物（如 [UI 功能状态说明](UI功能状态说明.md)）不可落后于代码。
- **格式**：源码 UTF-8（h/c）、构建文件 CRLF/LF 均可（生成器会归一化）；生成文件由脚本产生，不手工编辑 `src/default_ini.h`。
- **修复类改动**：附可复现验证手段（脚本用例输出/日志/截图），并在 [CHANGELOG](CHANGELOG.md) 主题级记录。

## 7. 分支与版本

| 分支 | 用途 |
|---|---|
| `main` | 稳定发布分支，始终可构建可运行；tag 打在此处 |
| `dev` | 集成分支，功能按批次合入 |
| `feature/<主题>` / `fix/<主题>` | 单个功能/修复 |

迭代循环（本地）：

```
git switch main && git switch -c feature/<主题>
开发 → 编译零警告 + 本地测试通过
git switch dev && git merge --no-ff feature/<主题>
git switch main && git merge --no-ff dev
git tag v1.2.0（或 v1.0.0-alpha.N）
删除 feature/<主题>
```

**两套版本独立管理**：**软件版本**以 `src/version.h`（`APP_VERSION`/数字宏）与 `res/udisktools.rc`（VERSIONINFO）为准（当前 `1.2.0`/`1.2.0.0`），发版 tag 使用软件版本；**配置文件版本**是 ini `[TOOLSINFO] VERSION`（当前 `1.0.0`），只标记配置内容，升级程序不改它，修改配置内容时由维护者决定是否同步。

## 8. 质量门禁清单（提交前）

- [ ] `make` 成功，零 error、无新增 `-Wall -Wextra` warning
- [ ] `pwsh scripts/gen_default_ini.ps1 -Check` exit 0（若改了 ini，已重生成 `src/default_ini.h` 并与 `profiles` 同批提交）
- [ ] `pwsh tests/run_tests.ps1` 全 PASS（以实际脚本为准）
- [ ] `--version` / `--check-ini` 行为符合预期（有效 0、无效 1、不弹窗）；`--version` 含软件版本 1.2.0，`--check-ini` 含配置文件版本
- [ ] 涉及控件的改动已对照 `ui/resource.h` 与 [控件位置对照图](控件位置对照图.html)，并更新 [UI 功能状态说明](UI功能状态说明.md)
- [ ] 涉及 ini 键的改动已更新 [使用手册](配置文件使用手册.md) 与 [规划书](UdiskTools软件规划书.md)
- [ ] 日志强制输出/恢复默认备份等安全行为未被破坏
- [ ] `git status` 无 `bin/build/logs/scratch` 等产物；文档链接无死链

## 9. 发布检查清单

1. 版本检查：**软件版本**三处一致（`src/version.h` 字符串/数字宏、`res/udisktools.rc` VERSIONINFO、README 状态区）；**配置文件版本**（ini `VERSION`）与手册/配置文档一致（两者独立，不要求彼此相同）。
2. 全量构建 + 测试 + CLI 冒烟通过。
3. `docs/CHANGELOG.md` 记录本批主题；用户文档（手册/UI 状态说明）已同步。
4. 产物：`bin/udisktools_v<软件版本>.exe`（单 exe，文件名带版本号）+ 示例 `profiles/UdiskTools.ini` + 文档。
5. 打 tag 并推送（远端启用后走 GitHub Actions 校验）。

## 10. 常见问题

| 现象 | 排查 |
|---|---|
| CI `Check default ini template` 失败 | `profiles/UdiskTools.ini` 改了未重生成/未同批提交；本地运行生成器后比较 diff |
| CI `Run tests` 失败而本地通过 | 检查 `-CC gcc` 与 PATH（CI 显式加入 `C:\msys64\mingw64\bin`）、路径大小写/换行 |
| CLI 冒烟失败 | `--check-ini` 需 `--ini` 指向存在文件；程序为 GUI 子系统，直接 `& exe` 捕获不到 stdout，需重定向 |
| 运行后中文乱码 | 源码/ini 编码：ini 支持 UTF-8±BOM / UTF-16LE/BE±BOM / GBK；源码应为 UTF-8 |
| 生成器 -Check 报"行尾风格不同"警告 | 仅行尾差异（内容一致）视为通过；若报 FAIL 则确有内容漂移 |
