# 策划方案：UdiskOps — 可移动磁盘自动化操作软件

> 版本：v1.0 ｜ 日期：2026-10-20 ｜ 状态：评审中

---

## 1. 项目概述

### 1.1 项目背景
在日常运维、生产线烧录、数据归档、质检抽检等场景中，经常需要对可移动磁盘（U盘、移动硬盘、SD卡、读卡器设备）进行批量、重复、可追溯的操作：复制数据、读取校验、速度测试等。人工操作效率低、易出错、无记录。

### 1.2 项目目标
开发一款**配置驱动**的可移动磁盘操作软件：
- 通过 JSON/YAML 配置文件定义操作序列（复制、读取、测速、校验等）
- 支持**自动模式**（插入磁盘后自动触发，无人值守）与**手动模式**（界面点选执行）
- 全程留痕：操作日志、结果报告、告警

### 1.3 核心价值
| 价值点 | 说明 |
|---|---|
| 配置即流程 | 一次编写配置，反复执行，减少人工误操作 |
| 无人值守 | 插盘自动执行，适合产线/批量场景 |
| 可追溯 | 每次操作生成带设备指纹的日志与报告 |
| 质量把关 | 内置读写校验（MD5/SHA256）与测速阈值判定 |

## 2. 需求分析

### 2.1 功能需求

#### F1 设备管理
- F1.1 监听可移动磁盘插拔事件（Windows: WM_DEVICECHANGE / WMI；跨平台可用 pyudev / IOKit）
- F1.2 读取设备信息：盘符、卷标、序列号、VID/PID、总容量、文件系统（FAT32/exFAT/NTFS）
- F1.3 设备白名单/黑名单：按序列号或 VID:PID 过滤，只对授权设备执行
- F1.4 设备指纹：序列号+容量+文件系统生成唯一 ID，用于日志关联

#### F2 操作引擎（配置驱动）

| 操作 | 说明 | 关键参数 |
|---|---|---|
| `copy` | 按规则复制文件/目录到磁盘（或从磁盘复制出） | 源/目标路径、通配符、覆盖策略、保留目录结构 |
| `read` | 读取文件并计算哈希校验（MD5/SHA256/CRC32） | 目标路径/通配符、哈希算法、期望哈希值（可选） |
| `write_verify` | 写入测试文件并回读比对（写入质量检测） | 测试文件大小、随机数据/模式数据 |
| `speed_test` | 顺序读/写、随机 4K 读/写测速 | 块大小、测试时长/数据量、文件数 |
| `format_check` | 检查文件系统、坏块快速扫描（逻辑层） | — |
| `erase` | 安全删除数据（覆写/快速格式化，可选功能） | 覆写次数、方式 |
| `wait` / `delay` | 操作间等待 | 秒数 |
| `report` | 生成阶段报告 | 格式 |

#### F3 配置文件系统
- 格式：JSON（默认）或 YAML
- 支持多套配置方案（profile），按设备指纹/卷标自动匹配
- 支持变量：`${DEVICE_LETTER}`、`${DEVICE_SERIAL}`、`${DATE}`、`${TIME}` 等
- 配置加载时进行 JSON Schema 校验，非法配置拒绝执行

配置示例：
```json
{
  "profile": "出厂检测-64GB",
  "match": { "min_capacity_gb": 60, "max_capacity_gb": 70 },
  "steps": [
    { "action": "speed_test", "mode": "seq_write", "block_kb": 1024, "size_mb": 512, "pass_mb_s": 30 },
    { "action": "speed_test", "mode": "seq_read",  "block_kb": 1024, "size_mb": 512, "pass_mb_s": 80 },
    { "action": "write_verify", "size_mb": 256 },
    { "action": "copy", "src": "./firmware/*", "dest": "${DEVICE_LETTER}:/firmware/", "overwrite": true },
    { "action": "read", "path": "${DEVICE_LETTER}:/firmware/*", "hash": "sha256" },
    { "action": "report", "format": "html" }
  ]
}
```

#### F4 执行控制
- F4.1 **自动模式**：后台服务监听插盘 → 匹配 profile → 自动执行 → 产出报告 →（可选）弹出磁盘、声光提示
- F4.2 **手动模式**：GUI 选择设备与配置方案 → 预览将执行步骤 → 执行 → 实时进度
- F4.3 执行策略：串行默认；可选多设备并行（按设备隔离任务）
- F4.4 失败策略：`stop`（停止）/ `continue`（记录后继续）/ `retry:n`
- F4.5 任务队列：多盘同时插入时排队处理

#### F5 报告与日志
- F5.1 每次任务生成报告：设备指纹、各步骤结果、测速曲线数据、哈希清单、耗时
- F5.2 报告格式：JSON（存档/程序消费）+ HTML（人读，含图表）
- F5.3 运行日志：分级（DEBUG/INFO/WARN/ERROR），按日期滚动
- F5.4 历史查询：按设备序列号、日期、结果检索历史报告

#### F6 用户界面
- 主界面：设备列表（实时状态）、当前任务进度、结果摘要
- 配置编辑器：可视化编辑步骤（或仅提供模板 + 文本编辑）
- 托盘常驻（自动模式）
- 简化 Web 界面（可选，Phase 2）

### 2.2 非功能需求
| 类别 | 要求 |
|---|---|
| 性能 | 测速采用大块直读直写，避免缓存干扰；单任务不阻塞 UI |
| 安全 | 白名单机制；erase 功能需二次确认；不触碰系统盘 |
| 可靠性 | 拔盘中断处理（任务标记 ABORTED，不留半成品报告）；断电恢复不要求 |
| 兼容性 | Windows 10/11 优先（x64）；Phase 2 考虑 Linux（产线工控机） |
| 日志合规 | 日志含设备序列号但不含用户数据内容 |

## 3. 技术方案

### 3.1 技术选型（推荐）

| 模块 | 选型 | 理由 |
|---|---|---|
| 语言 | Python 3.12 + PySide6 | 开发快、生态全；如需单文件分发可改 C#/.NET 或 Go+Web UI |
| 设备监听 | Windows API（RegisterDeviceNotification）/ WMI（wmi 库） | 原生插拔事件 |
| 磁盘信息 | psutil + ctypes(Win32 API GetVolumeInformation) | 容量、文件系统、序列号 |
| 测速 | 直接文件读写（O_DIRECT 思路：大 buffer + flush + 写后读），或封装 diskspd.exe | 规避系统缓存 |
| 哈希 | hashlib（SHA256/MD5）、zlib(CRC32) | 标准库 |
| 并发 | asyncio / threading + 任务队列 | 多盘并行 |
| 报告 | Jinja2 → HTML；Chart.js 内嵌（离线） | 测速曲线可视化 |
| 打包 | PyInstaller（单 exe）或 Inno Setup 安装包 | 现场部署 |

### 3.2 架构设计

```
┌────────────────────────────────────────────────┐
│                  UI 层 (PySide6)                │
│   设备面板 │ 任务进度 │ 配置编辑 │ 报告查看        │
├────────────────────────────────────────────────┤
│                  服务层 (核心)                   │
│  DeviceMonitor │ TaskScheduler │ ProfileManager │
├────────────────────────────────────────────────┤
│                  操作引擎层                      │
│  CopyOp │ ReadOp │ SpeedTestOp │ VerifyOp │ ... │
├────────────────────────────────────────────────┤
│                  基础设施层                      │
│  配置校验(Schema) │ 日志 │ 报告生成 │ 存储(SQLite) │
└────────────────────────────────────────────────┘
```

- **DeviceMonitor**：监听插拔，产出设备事件，匹配 profile 后投递给调度器
- **TaskScheduler**：任务队列 + 并行控制 + 失败策略
- **操作引擎**：每个操作实现统一接口 `execute(ctx: DeviceContext, params: dict) -> StepResult`，便于扩展新操作
- **存储**：SQLite 存历史任务/设备档案/测速记录

### 3.3 目录结构（规划）
```
udiskops/
├── core/            # 设备监听、调度、设备上下文
├── ops/             # 各操作实现（copy/read/speed_test/...）
├── config/          # 配置加载、Schema 校验、变量替换
├── report/          # JSON/HTML 报告生成
├── storage/         # SQLite 访问
├── ui/              # PySide6 界面
├── profiles/        # 内置配置方案模板
├── tests/
└── main.py
```

## 4. 开发计划

### Phase 1 — 核心引擎（第 1–3 周）
- 设备监听与信息读取、设备指纹
- 配置加载 + Schema 校验 + 变量替换
- copy / read / write_verify / speed_test 四个核心操作
- CLI 驱动（此时无 UI），JSON 报告

**里程碑 M1**：插上 U 盘，CLI 自动跑完配置流程并输出 JSON 报告。

### Phase 2 — 界面与体验（第 4–6 周）
- GUI 主界面（设备列表、进度、结果）
- 自动/手动模式切换、托盘常驻、多任务队列
- HTML 报告（含测速曲线）

**里程碑 M2**：可交付现场试用的 Beta 版。

### Phase 3 — 完善与发布（第 7–8 周）
- 白名单/黑名单、失败重试、安全擦除（可选）
- 历史记录查询、打包安装程序、文档
- 异常场景打磨：中途拔盘、磁盘满、只读盘、劣质盘假死（超时机制）

**里程碑 M3**：v1.0 正式发布。

## 5. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 测速受系统缓存干扰，结果虚高 | 数据失真 | 大数据量测试 + 写后强制 flush + 回读校验；可外挂 diskspd |
| 劣质 U 盘卡死/掉盘 | 任务挂起 | 所有 IO 设超时；监听设备移除事件强制作废任务 |
| 设备序列号缺失/伪造 | 白名单失效 | 指纹叠加 VID:PID+容量，容忍序列号为空的设备（仅日志标注） |
| FAT32 单文件 4GB 限制 | 复制/测速失败 | 前置检查目标文件系统并给出友好提示 |
|erase 误操作 | 数据损失 | 默认关闭，独立确认弹窗 + 二次输入确认 |
| Windows 驱动器占用（Explorer 预览） | 测速不准/复制失败 | 文档提示 + 尝试独占句柄检测 |

## 6. 验收标准（摘要）

1. 插入白名单 U 盘，自动模式 10 秒内开始执行匹配任务
2. 配置文件非法时拒绝执行并给出明确错误位置
3. copy 后 read 校验 100% 一致（哈希比对）
4. 测速结果与 diskspd 参考值偏差 < 10%
5. 任务执行中拔盘：任务标记 ABORTED，软件无崩溃，可继续下一次任务
6. 每次任务可查询到完整 JSON + HTML 报告
